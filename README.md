# 🔢 DigitVision AI Studio — Rebuilt CNN

A navy-blue Streamlit application for recognising handwritten **single digits and separated multi-digit numbers**. The project introduces a dedicated CNN rather than reusing the old MobileNetV2 input pipeline.

## Files

- `app.py` — Streamlit blue interface and inference
- `model_utils.py` — segmentation, grayscale preserving MNIST-style digit normalisation, centering, and predictions
- `train_model.py` — new CNN architecture, image augmentation, training and validation
- `evaluate_model.py` — accuracy, per-digit precision/recall/F1 and confusion matrix on the **untouched MNIST test set**
- `.streamlit/config.toml` — dark navy theme
- `requirements.txt` — Python dependencies
- `tests/test_model_utils.py` — preprocessing and multi-digit segmentation tests
- `digitvision_cnn.keras` — **generated by training; not included**

## 1. Set up locally in VS Code

Use **Python 3.11 or 3.12**. In VS Code, open the extracted project folder. In **Terminal > New Terminal** run:

```bash
python -m venv .venv
```

Activate it:

**Windows PowerShell:**
```powershell
.venv\Scripts\Activate.ps1
```

**macOS/Linux:**
```bash
source .venv/bin/activate
```

Then install:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 2. Train the new CNN (required)

```bash
python train_model.py --epochs 15
```

The script downloads MNIST (~11 MB on first use), reserves 6,000 **training-set images** for validation, and trains with mild augmentation. It writes `digitvision_cnn.keras` to the current folder. Training requires memory and CPU/GPU time. It was **not run** when this ZIP was packaged, so the included project does **not** claim measured accuracy or supply fake trained weights.

## 3. Evaluate on unseen MNIST images

```bash
python evaluate_model.py
```

The script evaluates the original 10,000-image MNIST test split, prints accuracy and per-digit metrics, and creates `evaluation.json`. Treat this as an objective MNIST benchmark, **not** proof of accuracy on arbitrary handwriting photos.

## 4. Run the app

```bash
streamlit run app.py
```

Upload a PNG/JPG. Choose handwriting polarity, inspect detected regions and the actual **28×28 grayscale** images sent to the CNN, then click **Recognise Number**. For numbers such as **20**, **125** and **2026**, separate digits by small gaps. If touching digits are incorrectly grouped, select **Manual cut positions** and enter x-coordinate boundaries.

### Deploy to GitHub + Streamlit Community Cloud

1. In your GitHub repo, upload `app.py`, `model_utils.py`, `train_model.py`, `evaluate_model.py`, `requirements.txt` and `.streamlit/config.toml`.
2. **Train first**, and add your new `digitvision_cnn.keras` file to the repository root. If GitHub rejects a large file, use Git LFS or another supported model storage option. **Do not rename your original MobileNetV2 model files.** They are no longer used by this app.
3. In Streamlit Community Cloud, use Python **3.11 or 3.12** and set `app.py` as the main file.
4. Wait for deployment and test images of isolated **4, 7, 8, 9** and multi-digit sequences.

## What is — and is not — improved

- **Yes:** dedicated MNIST CNN, correct matching input shape for the newly trained model, grayscale preserving preprocessing, centering, train/validation/test separation, labelled evaluation, segmentation preview, multi-digit assembly, dark theme.
- **Not guaranteed:** 100% accuracy. Handwriting outside MNIST, touching digits, cropping mistakes and lighting issues can still cause errors. Training and measuring performance are required to assess improvement.
- **Architecture changed intentionally:** the old saved `mnist_fine_tuned_model.keras` and `mnist_transfer_model.keras` expect **32×32 RGB with −1..1 values**. The **new** CNN expects **28×28 grayscale with 0..1 values**, and only `digitvision_cnn.keras` can be loaded by this new app.
